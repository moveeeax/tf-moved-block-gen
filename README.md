# tf-moved-block-gen

[![ci](https://github.com/moveeeax/tf-moved-block-gen/actions/workflows/ci.yml/badge.svg)](https://github.com/moveeeax/tf-moved-block-gen/actions/workflows/ci.yml)
[![go](https://img.shields.io/badge/go-1.22%2B-00ADD8?logo=go&logoColor=white)](https://go.dev)
[![license](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Renaming a Terraform resource is a destroy and a create, and Terraform will not
tell you they are the same thing. `tf-moved-block-gen` reads the plan, pairs the
destroys with the creates, and writes the `moved` blocks that turn a rebuild
back into a rename.

It also answers the other half of the question: which destroys are *not*
renames. `--fail-on-unexplained` turns that into a CI gate.

Go 1.22+, standard library only. No Terraform binary needed, no provider
credentials, no network.

## Install

```console
go install github.com/moveeeax/tf-moved-block-gen/cmd/tf-moved-block-gen@latest
```

Or build from a clone:

```console
go build -o tf-moved-block-gen ./cmd/tf-moved-block-gen
```

## Usage

```console
terraform plan -out tfplan
terraform show -json tfplan > plan.json
tf-moved-block-gen --plan plan.json --out moved.tf
```

Against the plan committed under `examples/`:

```console
$ tf-moved-block-gen --plan examples/plan.json
# Generated by tf-moved-block-gen. Review every block before you apply.
# 2 moved blocks proposed, 1 destroy still unexplained.

# confidence 0.85 | matched: ami, instance_type, monitoring, subnet_id, tags
moved {
  from = aws_instance.web
  to   = aws_instance.api
}

# confidence 1.00 | matched: description, ingress, name, tags, vpc_id
moved {
  from = module.app.aws_security_group.lb
  to   = module.edge.aws_security_group.lb
}
```

The human report goes to stderr, so `> moved.tf` stays clean HCL:

```text
2 moved blocks proposed, 1 destroy unexplained, 1 resource replaced in place
  rename  aws_instance.web -> aws_instance.api (0.85)
  rename  module.app.aws_security_group.lb -> module.edge.aws_security_group.lb (1.00)
  DESTROY aws_s3_bucket.legacy_logs (nothing of this type is created in this plan)
  replace aws_launch_template.workers
```

### As a CI gate

```yaml
- name: no unexplained destroys
  run: |
    terraform show -json tfplan > plan.json
    tf-moved-block-gen --plan plan.json --fail-on-unexplained --out moved.tf
```

Exit `1` means the plan destroys something that no rename explains — either a
real deletion you meant, or a refactor missing its `moved` block. Paste the
generated `moved.tf` into the configuration and the plan goes quiet.

## Flags

| flag | default | meaning |
| --- | --- | --- |
| `--plan FILE` | stdin | plan JSON from `terraform show -json tfplan` |
| `--out FILE` | stdout | where the HCL goes |
| `--min-confidence F` | `0.6` | threshold a pair must clear to become a `moved` block |
| `--json` | off | full report (moves, unexplained destroys, replacements) on stdout |
| `--fail-on-unexplained` | off | exit 1 when a destroy has no moved block |
| `--ignore GLOB` | — | skip matching addresses; repeatable or comma-separated |
| `--same-name-only` | off | only pair identical resource names, i.e. module moves |

Exit codes: `0` clean, `1` findings with `--fail-on-unexplained`, `2` a parse or
usage error.

## How it works

Every `resource_changes` entry is classified by its actions: a lone `delete` is
a move candidate's source, a lone `create` is a destination, and a
`["delete","create"]` pair is a replacement of the *same* address, which no
`moved` block can help with. `no-op`, `update`, `read` and data sources are
dropped.

Each (destroy, create) pair of the same resource type gets a confidence in
`[0,1]` from three signals:

- **attributes, weight 0.75** — the share of comparable attributes that are
  equal, with identifying ones (`name`, `tags`, `*_name`, `bucket`, `key`, …)
  counting triple. Server-assigned fields (`id`, `arn`, `owner_id`, timestamps)
  are excluded, and so is anything still unknown in the plan: a new resource's
  `id` is always unknown, and comparing it would only add noise.
- **name, weight 0.15** — Dice coefficient over character bigrams of the two
  local names. A module move keeps the name and scores 1; `web` → `api` scores
  0 and has to win on attributes alone.
- **index, weight 0.10** — same `count`/`for_each` key scores 1, a different key
  scores 0.4, so an index shift still pairs but ranks below an exact match.

Pairs above `--min-confidence` are assigned greedily, best first, and no address
is used twice. Ties break on the addresses, so the output is byte-identical
across runs on the same plan — the committed `examples/moved.tf` is a golden
file in CI.

Every destroy left without a partner is reported as an unexplained destroy, with
the reason: nothing of that type was created, or nothing scored high enough.

## One caveat

Confidence is a heuristic over plan attributes, not proof. Read the generated
blocks before you apply them — the comment above each one lists the attributes
that matched precisely so the diff is reviewable. The tool never edits your
configuration and never touches state.
